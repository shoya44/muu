# muu 前提資料（コンセプト・方針・原則）

更新：2026-09-26。開発中に迷ったとき、ここに照らして判断する。仕様（specification.md）や設計（design.md）と矛盾したら、本書を優先し、両者を直す。

## 1. コンセプト

**「友人と共有する、自分たちだけのSpotify」。**

R2 に置いた MP3 を、URL を知る友人がスマホのホーム画面から開き、迷わず聴き、保存して、通信が無くても聴き続けられる。それ以上のことはしない。

## 2. 利用者像と利用場面

- 利用者は数人の友人。技術者ではない。説明なしで使える必要がある。
- 片手で、移動中や作業中に、画面をあまり見ずに使う。
- 曲数は数十〜数百。検索より一覧と並び替えで足りる規模。
- 管理者（アップロード・削除）は 1〜2 人。管理操作は稀で、聴く操作は毎日。

## 3. 優先順位

判断に迷ったら、上にあるものを守る。

1. **既存の音声と再生を壊さない**。更新・同期・失敗・仕様変更のどれも、端末に保存した曲と今の再生を止める理由にならない。
2. **聴くまでの手数を減らす**。起動して 1 タップで再生。前回の続きから。
3. **画面は最小**。出す情報は「今それを決めるのに必要なもの」だけ。
4. **仕組みは最小**。同じことを 2 か所で管理しない。無くても成り立つ層は置かない。
5. 見た目の整い、機能の多さ。ここは最後。

## 4. 設計原則

### 正はひとつ

- 共有データの正は R2 のオブジェクト。DB・索引・キャッシュはそれの写しであり、食い違えば写しを捨てる。
- 再生数も R2 の 1 オブジェクト（`_stats.json`）に置く。DB は持たない。無くても壊れても、再生と保存は変わらない（全曲 0 回に見えるだけ）。
- 個人データ（プレイリスト、保存済み、再生状態）の正は端末。サーバーは知らない。
- 「同期」「修復」「整合性チェック」という処理を必要とする設計は、正が複数ある兆候。まず構造を疑う。

### 表示は「いま再生できる曲」だけ

- R2 に無い、壊れている、属性が欠けている曲は Home に出さない。理由も出さない。
- 例外は My Playlist の端末保存済み曲。利用者が自分で入れたものだけはグレーで残し、消す前に警告する。

### 状態と操作をひとつにする

- 保存アイコンは状態表示であり、押せば操作になる。トグルは中間状態を持つ。
- 「開く / 閉じる」「表示 / 非表示」の状態を増やさない。キューは再生画面の続きに常にある。
- 完了した処理は結果であって状態ではない。トーストで一度言い、消す。

### 操作は 1 タップ、確認は取り消せないときだけ

- 行タップで即再生。長押しはドラッグ開始だけ。
- 確認ダイアログは「端末の音声が消える」「R2 から消える」のときだけ。それ以外は即実行し、必要なら Undo をトーストに置く。
- タップ領域は 48dp 以上。再生の主要操作は画面下部、親指の届く範囲に置く。

### 言葉より形

- テキストラベルは選択中のタブ、ボタンの補助、警告文だけ。使うなら短い英語。
- アイコンは Material Symbols のみ。意味が一目で伝わらないアイコンは、ラベルを足す前に置き方を疑う。
- 色だけで状態を伝えない。色は塗りであり、意味は形と位置で伝える。

### 起動は待たせない

- 前回の一覧を即表示し、裏で取り直す。全画面 Loading は初回だけ。
- 更新は知らせるが割り込まない。再生中は適用しない。

### 依存を増やさない

- フレームワーク、ビルド、CDN、外部フォント、DB、いずれも「無いと動かない」ものにしない。
- 追加する層には「これが無いと何ができないか」を一文で言えること。言えなければ入れない。

### 誰でも読める、管理者だけが書ける

- 読み取りは無認証。URL を知る人は全曲を聴け、保存できる。これは前提であり弱点ではない。
- 書き込みはパスワードひとつ。認可の仕組みを増やさない。

## 5. 見た目の原則

- Material Design 3 準拠、ダーク固定。M3 のロール名（surface, on-surface, primary…）で色を扱い、Hex は theme.css にだけ書く。
- パレットは指定の 5 色（#212129 / #323949 / #3d3e51 / #40445a / #4c5265）。文字とアイコンは白系。差し色は塗り専用。
- Spotify 的な密度。黒地、細い行、カバー主体。影・グラデーション・常時アニメーションは使わない。
- 動きは指に追従するものだけ（スワイプで閉じる、ドラッグで並べる）。装飾のための動きは置かない。

## 6. やらないこと

- 曲ごとのカバー、タグ編集、イコライザー、履歴画面。例外として、管理者だけが全員の再生を最後に聴かれた順に見られる（Recently played。誰が聴いたかは持たない。2026-10-04）。
- いいね、誰が聴いたかの表示、再生数による並べ替え。再生数は曲ごとの合計を Details にだけ出す（2026-09-29）。
- 歌詞の同期表示（タイムタグ）。歌詞はプレーンテキストを再生画面のカバー枠に出すだけ。
- 端末間のプレイリスト同期、再生位置の同期、アカウント。
- 自動 Wi-Fi 判定、自動保存の強制。保存は利用者が始める。
- 検索。必要になったら一覧のフィルタとして足す。
- 管理者向けの一括操作（一括リネーム、一括移動）。R2 のダッシュボードでやる。1 曲ずつの曲名変更・フォルダ移動は設定画面でできる（2026-09-29）。

## 7. 判断チェックリスト

新しい機能・変更を入れる前に、全部「はい」か確かめる。

- [ ] 保存済みの曲と再生中の曲に影響しないか。
- [ ] 正が増えていないか（R2 と端末以外に真実を持たせていないか）。
- [ ] 画面に増える要素は、いま決めるのに必要か。
- [ ] タップ数は増えていないか。
- [ ] 無くても動く層を足していないか。
- [ ] 数人の友人が説明なしで使えるか。
- [ ] 「やらないこと」に触れていないか。触れるなら本書を先に直す。
